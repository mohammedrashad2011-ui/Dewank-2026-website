## Stage 5 — email delivery worker (draft)
SMTP delivery is deliberately disabled until a verified sender and owner recipient are configured. Hostinger Email uses smtp.hostinger.com:465 (TLS) or 587 (STARTTLS); confirm the actual mailbox provider before entering credentials. Use SMTP_USER, SMTP_PASSWORD, CRM_NOTIFY_TO, optional SMTP_HOST/SMTP_PORT and CRM_NOTIFICATIONS_ENABLED=true on the private host only. Cron on Hostinger Node apps does not automatically inherit app environment variables; follow the official Hostinger Node cron documentation and use a protected server-only environment file, never source control. The worker is bounded, uses lease-based claims, retries up to five times, and uses a deterministic Message-ID; SMTP delivery is at-least-once (duplicates possible after a crash). Terminal failures need an operator review. CI tests use a fake mail sender and real isolated MySQL; no real email is sent. Node worker script scripts/crm-notify.mjs requires nodemailer pinned from the CI-generated lock delta before release. It cleans only stale rate-limit buckets. Migration remains unapplied on Hostinger. No live activation or cron setup yet.
