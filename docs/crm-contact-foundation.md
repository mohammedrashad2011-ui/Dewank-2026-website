# DEWANK lead capture — foundation (draft)
This stage is intentionally not wired into the live form. No changes to the current WhatsApp links, GTM, pricing, SEO or production data. Hostinger production uses DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD as server-only environment variables. Never expose them as NEXT_PUBLIC variables or log their values. Keep external connections disabled.

## Next implementation gate
- Install a pinned supported mysql2 version with npm, commit package.json and the npm-generated package-lock.json together, run npm ci and npm run build. Do not hand-edit lock metadata.
- Verify staging connection with SELECT 1 from a server runtime; production credentials must never be copied into Vercel Preview. Use an isolated MySQL staging instance or private staging service, not public access to production.
- Apply db/mysql/001-crm-leads.sql in staging, validate table definitions, then apply to the designated production database only after approval. Use a separate least-privilege runtime user if supported; no DDL permissions for routine submissions.
- Build POST /api/leads using server-side validation, strict content type, streamed request size cap (16 KiB), same-origin checks, prepared statements, bounded connection pool, persistent rate limiting and honeypot. Never log raw bodies, phone, email or database errors to clients. Return generic errors and retain form values on failure. Use a UUID requestId per logical submission, transactional unique-key handling and return the existing reference only to a matching retry; avoid leaking other records.
- Insert lead and email outbox atomically, acknowledge success only after commit. Send notification via a verified provider/worker; notification failure must not lose the saved lead. No automatic WhatsApp window. Optional direct WhatsApp link after success with reference only.
- Use the existing Arabic/English contact pages, with name and international WhatsApp number required, service preselected from an allowlisted offer, other details optional. Link from naming offer to /contact?offer=brand-naming#brief-form. Preserve direct WhatsApp route and all existing design/SEO. Match AR/EN service IDs to current catalog and add translations, accessible validation and consent/privacy notice.
- Attribution: read permitted first-party campaign parameters only when analytics consent permits; distinguish missing/unknown from direct traffic, never include personal data in analytics. Fire generate_lead once after a confirmed new commit, not on validation, click or retry. Keep current whatsapp_click events and GTM v15 untouched. No Google Ads import until separate approval.
- Update the existing CRM sheet with a protected sync only after database capture works; do not put customer data in public previews, logs or analytics. Verify access, retention and deletion workflow.
- Run node --test tests/crm-validation.test.mjs; test mobile Safari/Chrome/Samsung and desktop, direct link, selection, duplicate requests, bad input, DB outage, notification outage, privacy, attribution and production build. Preview must not write real customer data or send production notifications. Do not merge without explicit approval.
